QCL-CE 使用文档

安装、启动器用法、以及遇到问题时的排查方法。当前最新版 v3.1.7；Beta 1.0.5 是独立测试通道，差异见安装说明。

安装

v3.1.7 与 Beta 1.0.5

  • v3.1.7 是当前最新正式版，包名 com.qcl.launcher.ce，可直接覆盖同包名的旧 CE 版本。
  • Beta 使用独立包名 com.qcl.launcher.ce.beta，可以和 v3.1.7 / 官方版同时安装，不需要卸载。
  • 游戏目录仍共用 /sdcard/QCL，实例、存档、备份通用；Beta 的应用内部设置与正式版隔离。
  • v3.1.7 与 Beta 都是 Android Debug 签名，只用于测试。正式签名版本需要提供 keystore 后再构建。
  • Beta 的检查更新只读取预发布版本，不会误推正式版；最新版可下载 v3.1.7。

装之前

  1. 确认手机是 arm64（绝大多数现代手机都是）；模拟器 x86_64 不能装。
  2. 如果之前装过别的 Beta 签名，先卸载再装；v3.1.7 / 官方版不用卸载。
  3. 测试前建议先备份存档。v3.1.7 与 Beta 共用 /sdcard/QCL。

直接下载： 最新版 v3.1.7 直链 ｜ 国内镜像（gh-proxy） ｜ Beta 1.0.5

gh-proxy 只是把同一条 GitHub 直链转发一遍，下载到的文件完全一样。 也可以到 Releases 页面查看全部发布：

文件用途
QCL-CE-v3.1.7-arm64.apk最新正式版，Debug 签名。
QCL-CE-1.0.5-beta-arm64.apkBeta 测试包，独立包名，可与正式版共存。

第一次启动

第一次打开会解压内置运行时，约 452 MB，需要几分钟。这一步是离线解压 —— 断网也能装完。

如果卡在这一步不动，先确认手机剩余空间够（建议留 2 GB 以上）。

确认手机架构

本项目只提供 arm64 包。确认方法：

  • 设置 → 关于手机 → 处理器，写着 arm64-v8a 或 aarch64 就是。
  • 2017 年之后的手机基本都是 arm64。
  • 如果是 x86_64（模拟器常见），需要另外构建 x86_64 包。

使用

启动游戏

  1. 主页显示当前要启动的版本和已装版本数（都是实时读出来的）。
  2. 点启动游戏即可。
  3. 启动日志会实时显示在弹窗里 —— 出问题就看那里。

切换账号

点主页的头像就能切换 ✓（2.0.8 起）。也可以长按顶部的账号按钮。

会弹出一个账号列表，点哪个就切到哪个。

第三方登录（外置登录）

账号页第 4 个按钮 「第三方登录 / 外置登录」 —— 支持 authlib-injector 的服务器 ✓

  • 点它 → 选服务器类型 → 填服务器地址
  • 支持 Blessing Skin、LittleSkin 这类外置登录皮肤站
  • 登录后皮肤和披风都走那个服务器 ✓
这个功能一直都有 —— 2.0.8 之前它叫「添加认证服务器」， 名字不容易看懂，所以很多人以为没有。现在改成了「第三方登录 / 外置登录」。

装版本

  1. 左侧「≡ 菜单」→ 下载，或直接进版本列表。
  2. 选版本安装。下载会走国内镜像加速。
注意：远古版本（很老的 alpha/beta）需要额外的中文补丁，QCL-CE 会自动处理。

版本列表每一行右边有个地球图标 —— 点一下会打开这个版本的 Minecraft Wiki 页面 ✓ 想查某个版本加了什么内容时很方便。

Legacy Fabric（1.8 ~ 1.13）

「下载 → 安装游戏」页里多了一行 Legacy Fabric ✓

它是 Fabric 给 1.8 ~ 1.13 这些老版本用的分支 —— 界面和普通 Fabric 一模一样， 只是版本列表来自 meta.legacyfabric.net。

Legacy Fabric API 是个模组，不是加载器 —— 到「下载 → 模组」里搜 legacy-fabric-api 就能找到。

Cleanroom（1.12.2 的 Forge 延续版）

插件页搜 Cleanroom ✓

  • 它是 Minecraft 1.12.2 上 Forge 的延续版（不是 fork，是逐步独立的现代化版本）
  • 只支持 1.12.2 —— 模组也要用 1.12.2 的
  • 运行时要 Java 25，启动器里已经内置了
  • 版本列表来自官方 Maven 仓库，装了会自动用 MultiMC 的安装流程

装模组

在下载 → 模组里搜索并安装。安装时 QCL-CE 会自动把前置也一起装上：

  • 只装必需的前置，可选/不兼容/内置的会跳过。
  • 会按你当前的游戏版本挑合适的前置版本。
  • 已经装过的会自动跳过，不会重复下载。
  • 整条依赖链都会拉下来 —— A 需要 B、B 又需要 C 时，C 也会被装上。

装整合包

「安装包」里选整合包文件即可。目前支持：

格式说明
MultiMC / Prism✓ 完整支持
Modrinth（.mrpack）✓ 支持，限 Fabric 加载器
CurseForge✓ 支持，限 Fabric 加载器
HMCL / MCBBS✗ 还没接通，先手动解压把 mods/ 拷进游戏目录
为什么只支持 Fabric？ Fabric 的官方 profile JSON 本身就是完整版本 JSON， 可以直接落盘，不用跑安装器。Forge / NeoForge 需要运行官方安装器，还没接。

装整合包时会自动下载游戏本体，并逐条列出下载任务，能看到装到哪一步。

深色模式

内置插件页 → 界面 → 深浅色模式，三个选项：跟随系统 / 始终浅色 / 始终深色。

不用去改手机系统设置，在应用里就能切，方便试。

菜单排版

点左侧「≡ 菜单」打开功能菜单，右上角有排版按钮：

  • 勾选要显示哪些入口
  • 用 ↑↓ 调顺序
  • 保存 / 恢复默认

界面排版自定义

长按任意页面就能进编辑模式：

  • 单击一个控件 = 显示 / 隐藏
  • 长按控件再拖动 = 在同层里换位置
  • 底部浮动条：保存 / 取消 / 恢复默认

支持 13 个页面：主页、下载、版本列表、设置、账号、游戏管理、大厅、实验室、备份、启动诊断、资源下载、插件、联机。

排版是「进页面时应用」的 —— 改完要退出再进主页才生效，不会立刻变。

想把排版分享给别人：插件页 → 界面 → 排版导入 / 导出 → 复制到剪贴板 → 发群里。别人复制后点「从剪贴板导入」即可。

控键布局导入（3.1.7 / Beta 1.0.5 已支持）

入口：设置 → 游戏设置 → 控键布局 → 管理，或 版本设置 → 管理控键。 在「管理触控布局方案」里点 从本地导入布局，选择文件即可。

来源文件
Fold Craft Launcher（FCL）.json（controllerVersion 21）
Zalith Launcher 2.json（editorVersion 12）
Zalith Launcher（ZL1）.json（version 8）
HMCL-PE.hmclpe（加密 ZIP，内部密码自动处理）
  • 导入后另存为新布局，不会覆盖你已有的布局；同名会自动加 (2)。
  • FCL 的图层、ZL2 的 layer、ZL1 的抽屉都会转成 QCL 的子布局；抽屉默认隐藏，由把手按钮展开。
  • 按键会从各家的键码统一映射到 GLFW；ZL2 的 switch_layer / 启动器事件会转成 QCL 的可见性控制或菜单/输入法开关。
  • ZL1 的像素坐标表达式会在参考屏幕上求值后转成百分比，换设备仍保持相对位置。
  • 样式（颜色、圆角、描边、文字大小）尽量还原；ZL2 的文字粗体/斜体等 QCL 没有的属性会忽略。
兼容性：FCL 的方向控件如果改过方向键（不是 WASD），QCL 摇杆仍按 WASD 输出； ZL1 的虚拟鼠标开关、ZL2 的穿透/滑动属性没有一一对应项，会退化为普通按钮。

插件

左侧「≡ 菜单」→ 插件。顶部有搜索框，可以按名字搜。

插件分几类：下载、界面、资源、模组、账号、联机、系统、安全与备份等。

插件市场

插件页 → 资源 → 插件市场，可以直接在应用内安装资源型插件。

  • 市场里的插件是资源型的（控键布局 / 界面排版）—— 启动器没有插件运行时，所以不加载代码。
  • 每个包都会校验 sha256，对不上就拒装。
  • 安装完如果是排版类，退出再进主页生效；控键类到「设置 → 控键布局」里选。
  • 市场网页：weeb123321.github.io/QCL-Plugins

手机开服

入口：侧栏 游戏 → 服务器列表，或插件页搜索 手机开服管理。列表会列出已经创建的服务器， 可以直接启动、进入控制台，也可以给某个服务器下载插件/模组。

能力说明
服务端类型原版、Paper、Purpur、Fabric、Forge、NeoForge（Forge / NeoForge 为实验性，需要跑官方 installer）
下载与校验官方源 / Paper API / Purpur API / Fabric Meta / Forge Maven；原版与 Paper 校验 SHA-256，Purpur 校验 MD5，可改用本地包
运行列表直接启动；独立 :server 进程 + 前台服务，支持 WakeLock / WifiLock，退出启动器不中断
控制台启停 / 重启 / 直连启动、实时日志、发送服务端命令
玩家与配置ops / whitelist / banned 管理，直接编辑 server.properties
插件 / 模组下载服务器列表 → 下载插件/模组：Modrinth / CurseForge 搜索、按服务端版本筛选、选择版本后下载到 plugins 或 mods
模组 / 插件管理Paper / Purpur 管理 plugins，Fabric / Forge 管理 mods；支持启用/停用、移入回收目录
世界备份世界 + 核心配置打包 ZIP；恢复前自动再做一份 pre-restore 备份
联机共享配合 Terracotta 房间，向 Minecraft 局域网广播端口，朋友可直接扫描加入

游戏入口与按键同步

侧栏原来的 实例 已改名 游戏。点它会先让你选 游戏实例 或 服务器列表； 下方是按键同步：把当前实例的控键布局一键同步给所有游戏实例，或恢复默认。

  • 同步只改每个实例的 控键布局选择，不动内存、Java、渲染器和存档。
  • 恢复默认只恢复通过启动器改过、而且之后没有被外部修改的实例；手动改过 qcl.cfg 的会跳过。
  • 先在「版本设置 → 管理控键」里把当前实例改好，再回来同步。
注意：同一时间只运行一个服务端；手机性能有限，建议 2 GB 以上内存并保持充电。 Forge 安装器需要联网且耗时较长；NeoForge 暂未接入。服务端下载的插件/模组需要重启服务端生效， 前置/依赖请按说明单独下载。开服链路还没有经过真机验收，遇到问题请附控制台日志和启动诊断。

排错

出问题先做这个

「我的 → 启动诊断」→ 分享给作者。

这一页会生成一份完整报告：设备信息、上次启动断点、本次启动路标、系统记录的进程退出原因、以及输入链路自检。把这段发出来，绝大多数问题能直接定位。

一打开就闪退

按顺序排查：

  1. 先卸载官方版 QCL。两个包签名不同却曾共用同一个数据目录，会导致读写失败。
  2. 清除应用数据再打开。
  3. 看日志：/sdcard/QCL-CE/crash.log（1.9.3 起的新路径）。
  4. 把「启动诊断」的报告发出来。

游戏里点不了

表现是画面正常、游戏也能进去，但点什么都没反应。这类问题的根因在输入层，从界面看不出来。

去「我的 → 启动诊断」，报告里有一段 ----- 输入链路自检 -----，它会列出：

  • 进程实际加载了哪些输入相关库（读 /proc/self/maps）
  • 磁盘上有哪些输入库
  • 控制布局目录的内容

判读方法写在报告末尾。把这段发出来即可定位。

插件市场连不上 / 网页打不开

先看浏览器报什么错 —— 不同错误码指向完全不同的原因：

浏览器报错真正的原因怎么办
ERR_PROXY_CONNECTION_FAILED 系统代理坏了（最常见） 见下面的「关掉系统代理」
ERR_CONNECTION_TIMED_OUT / 一直转圈 域名被拦 / 网络太慢 App 会自动换镜像重试，也可以挂代理
浏览器能打开，但 App 里不行 App 侧的问题 去「我的 → 启动诊断」把报告发出来
关掉系统代理（最常见的原因）：
  • Windows：设置 → 网络和 Internet → 代理 → 关掉「使用代理服务器」
  • 安卓：设置 → WLAN → 长按当前网络 → 修改网络 → 代理 → 无

常见情况：某个代理 / VPN 客户端已经关了， 但系统代理设置还留着 —— 于是浏览器和 App 都往一个死掉的端口发请求。

2.0.5 起，App 里读市场索引会先直连、失败再走系统代理， 所以代理坏了也能读到 ✓ 但修好代理更彻底。

下载失败

  • 默认会走国内镜像。如果某个镜像挂了，会自动回退到官方源。
  • 可以在插件页的「下载镜像自定义」里换一个镜像。
  • 如果一直失败，检查网络是否有限制。

装不上 / 提示签名冲突

  • 签名冲突：官方版没卸干净。到「设置 → 应用」卸载 QCL 后再装。
  • 版本降级：装了更高 versionCode 的包。卸载后重装即可。
  • 解析包出错：文件没下载完整，重新下载。

FAQ

能和官方版同时装吗？

能。QCL-CE 的包名是 com.qcl.launcher.ce，和官方版不同，可以共存。

装 QCL-CE 会不会影响官方版的存档？

不会动官方版的存档。但两者曾经共用同一个外部目录，所以建议先把官方版的存档备份一份再折腾。

为什么只提供 arm64？

因为绝大多数手机是 arm64。内置运行时会按架构分包，只带一份能让安装包小约 100 MB。

支持正版登录吗？

支持微软账号登录。离线账号也能用，但只能进单人游戏或离线服务器。

怎么反馈问题？

到 GitHub Issues 提，或者带上「启动诊断」的报告。
